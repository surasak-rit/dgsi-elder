# ชุดคำถามสำหรับดูงานโครงการ ERP SAP S/4HANA — คณะแพทยศาสตร์ศิริราชพยาบาล

> **เป้าประสงค์ของการดูงาน:** นำประสบการณ์การทำโครงการของคณะแพทย์ฯ มาช่วยวางแผนดำเนินโครงการของเรา
> ตามแนวทาง **Greenfield (ขึ้นระบบใหม่)** และ **Fit-to-Standard (ปรับองค์กรตามมาตรฐาน SAP)**
> พร้อมออกแบบกระบวนการทำงานให้สอดคล้องกับเป้าประสงค์
>
> **วิธีใช้:** คำถามจัดกลุ่มตามหัวข้อ ★ = คำถามลำดับความสำคัญสูง (ถามให้ได้ถ้าเวลาจำกัด)

---

## 1. ภาพรวมโครงการและการตัดสินใจเชิงกลยุทธ์ (Strategy & Governance)

- ★ อะไรคือ "แรงผลักดัน" (business driver) หลักที่ทำให้ตัดสินใจขึ้น SAP S/4HANA และทำไมถึงเลือกแนวทาง **Greenfield** แทนที่จะ migrate ระบบเดิม (Brownfield/Selective)?
- ★ เลือกรูปแบบ deployment แบบไหน — On-Premise, Private Cloud (RISE with SAP), หรือ Public Cloud (GROW)? เหตุผลในการตัดสินใจ และข้อดี/ข้อจำกัดที่เจอจริง?
- โครงสร้างการกำกับดูแลโครงการ (Project Governance) เป็นอย่างไร — มี Steering Committee ระดับไหน, ผู้บริหารสูงสุด (Sponsor) มีบทบาทมากน้อยแค่ไหนในการตัดสินใจเรื่องยากๆ?
- ขอบเขต (scope) ของ phase แรกครอบคลุมโมดูลอะไรบ้าง? ใช้เกณฑ์อะไรในการตัดสินว่าอะไรอยู่ใน scope / อะไรเลื่อนไป phase ถัดไป?
- ถ้าย้อนเวลากลับไปได้ มีการตัดสินใจเชิงกลยุทธ์อะไรที่อยากทำต่างจากเดิม?

## 2. แนวทาง Fit-to-Standard (หัวใจของการดูงาน) ★★★

- ★ นิยาม "Fit-to-Standard" ในบริบทของคณะฯ คืออะไร — ยึดมาตรฐาน SAP Best Practice ได้กี่ % จริง และส่วนที่ต้องปรับแก้มีสัดส่วนเท่าไหร่?
- ★ กระบวนการ Fit-to-Standard Workshop ดำเนินการอย่างไร — ใครเข้าร่วม, ใช้ระยะเวลากี่รอบ/กี่สัปดาห์, ใช้ระบบ sandbox/demo ให้ user ลองจริงหรือไม่?
- ★ เมื่อเจอ "gap" ระหว่างกระบวนการเดิมกับมาตรฐาน SAP มีหลักเกณฑ์ตัดสินใจอย่างไรระหว่าง (1) ปรับกระบวนการองค์กรให้เข้ากับระบบ vs (2) customize ระบบ? ใครเป็นผู้ชี้ขาด?
- ★ จัดการกับแรงต้าน "แต่เดิมเราทำแบบนี้มาตลอด" จากหน่วยงานอย่างไร โดยเฉพาะกระบวนการที่ผูกกับระเบียบราชการ/มหาวิทยาลัย?
- นโยบาย **Clean Core** เป็นอย่างไร — ควบคุม custom code (RICEFW) ไม่ให้บานปลายด้วยวิธีใด, มี governance board อนุมัติทุก customization หรือไม่?
- ระเบียบ/ข้อบังคับของภาครัฐหรือมหาวิทยาลัยข้อไหนบ้างที่ "บังคับ" ให้ต้อง customize เลี่ยงไม่ได้ (เช่น ระบบพัสดุภาครัฐ, GFMIS, ภาษี, การเบิกจ่าย)? แก้ปัญหาอย่างไร?
- สุดท้ายมี custom object กี่รายการ และมีบทเรียนเรื่อง technical debt ที่ตามมาหรือไม่?

## 3. การออกแบบกระบวนการทำงาน (Business Process Design / BPR)

- ★ ใช้ end-to-end process อะไรเป็นกรอบ (เช่น Procure-to-Pay, Record-to-Report, Hire-to-Retire)? มีการทำ process mapping ก่อนหรือหลังเลือกระบบ?
- ★ ใครเป็น "Process Owner" ของแต่ละกระบวนการ และเขามีอำนาจตัดสินใจข้ามหน่วยงานได้จริงหรือไม่?
- การออกแบบกระบวนการใหม่ทำให้ต้อง "ยุบ/รวม/ปรับ" โครงสร้างหน่วยงานหรือตำแหน่งงานหรือไม่ อย่างไร?
- มีการใช้เครื่องมืออะไรช่วยออกแบบ/บันทึกกระบวนการ (เช่น SAP Signavio, Solution Manager, Visio)?
- กระบวนการที่ออกแบบใหม่ วัดผลว่า "ดีขึ้น" จากเดิมด้วยตัวชี้วัดอะไร (เช่น ลด lead time, ลดขั้นตอน, ลดกระดาษ)?

## 4. โครงสร้างทีมและพันธมิตร (Team & SI Partner)

- ★ โครงสร้างทีมโครงการเป็นอย่างไร — สัดส่วนคนภายในคณะฯ vs ที่ปรึกษา (SI/Implementation Partner)?
- ★ เลือก SI Partner ด้วยเกณฑ์อะไร และประเมินว่าการทำงานร่วมกันเป็นอย่างไร มีข้อควรระวังในการทำสัญญา/TOR อะไรบ้าง?
- บทบาท **Key User / Super User** ถูกดึงมาจากหน่วยงานอย่างไร — ปล่อยจากงานประจำเต็มเวลาหรือไม่, มีแรงจูงใจอะไรให้เขา?
- มีการสร้าง Center of Excellence (CoE) หรือทีม support ภายในเพื่อดูแลระบบหลัง go-live หรือไม่?
- ปัญหาเรื่องคนที่หนักที่สุดคืออะไร — ขาดคน, คนลาออกกลางโครงการ, ทักษะไม่พอ?

## 5. การบริหารการเปลี่ยนแปลง (Organizational Change Management)

- ★ แผน OCM ทำอย่างไร — สื่อสาร, อบรม, สร้าง change agent เครือข่ายอย่างไร?
- กลุ่มผู้ใช้ที่ต่อต้านมากที่สุดคือใคร และวิธีเอาชนะใจเขา?
- การอบรม (training) ทำแบบไหน — train-the-trainer, e-learning, คู่มือ? วัดความพร้อม user ก่อน go-live อย่างไร?
- ผู้บริหารระดับสูงมีส่วนร่วมในการ "นำการเปลี่ยนแปลง" อย่างเป็นรูปธรรมอย่างไร?

## 6. ข้อมูลและการโยกย้าย (Data Migration)

- ★ กลยุทธ์ data migration เป็นอย่างไร — ย้ายข้อมูลเดิมมากน้อยแค่ไหน, ตัดสินใจอย่างไรว่าจะไม่ย้ายอะไร (เช่น historical data)?
- คุณภาพข้อมูลต้นทาง (data cleansing) เป็นปัญหาแค่ไหน และเริ่ม cleansing ตั้งแต่เมื่อไหร่?
- ใช้เครื่องมืออะไร (SAP Migration Cockpit, LTMC) และทำ mock migration กี่รอบก่อนจริง?
- Master data governance หลัง go-live ดูแลอย่างไรไม่ให้ข้อมูลเละอีก?

## 7. การบูรณาการระบบ (Integration)

- ★ SAP ต้องเชื่อมกับระบบอื่นอะไรบ้าง (เช่น ระบบโรงพยาบาล HIS, ระบบงานบุคคล, GFMIS, ธนาคาร)? ใช้เทคโนโลยีอะไรเชื่อม (SAP BTP/PI/PO, API)?
- interface ไหนที่ยากที่สุดและใช้เวลามากเกินคาด?
- มีการวางสถาปัตยกรรมแบบ side-by-side extension บน BTP เพื่อรักษา clean core หรือไม่?

## 8. แผนงาน งบประมาณ และการทดสอบ (Timeline, Budget & Testing)

- ★ ใช้ระเบียบวิธี (methodology) อะไร — SAP Activate? แบ่งเป็นกี่ phase และใช้เวลาจริงเทียบกับแผนเดิมต่างกันแค่ไหน?
- ★ งบประมาณบานปลายหรือไม่ ส่วนไหนที่ประเมินต่ำไป (underestimate) มากที่สุด?
- ทำ testing กี่รอบ (SIT, UAT, Regression) และใช้เกณฑ์อะไรตัดสินว่า "พร้อม go-live"?
- เลือกกลยุทธ์ cutover แบบไหน — Big Bang หรือ Phased? เพราะอะไร และช่วง cutover จริงเป็นอย่างไร?

## 9. Go-Live และการดูแลหลังใช้งาน (Go-Live & Hypercare)

- ★ ช่วงแรกหลัง go-live (hypercare) เจอปัญหาหนักอะไรบ้าง และใช้เวลากี่สัปดาห์กว่าจะนิ่ง?
- ตัวชี้วัดความสำเร็จของโครงการ (success metrics) หลัง go-live คืออะไร และบรรลุหรือไม่?
- โมเดลการ support ระยะยาว (level 1/2/3) และค่าใช้จ่าย license/maintenance รายปีเป็นอย่างไร?

## 10. บทเรียนสำคัญ (Lessons Learned) ★★★

- ★ ถ้าให้เลือกมา **3 ปัจจัยแห่งความสำเร็จ (Critical Success Factors)** ที่สำคัญที่สุด จะเป็นอะไร?
- ★ **3 ข้อผิดพลาด/กับดัก (pitfalls)** ที่อยากเตือนองค์กรที่กำลังจะเริ่มทำแบบเรา?
- ★ ถ้าจะให้คำแนะนำองค์กรที่กำลังจะเริ่มโครงการ greenfield + fit-to-standard เพียง 1 ข้อ จะเป็นอะไร?
- มีอะไรที่ "ไม่มีใครบอกล่วงหน้า" แต่กลายเป็นเรื่องใหญ่ในโครงการจริง?
